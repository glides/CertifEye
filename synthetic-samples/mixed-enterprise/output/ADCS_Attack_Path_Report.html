Primary attack paths

A concise view of the highest-priority current-run relationships. These cards describe evidence-backed prerequisites, not proof of successful abuse.

PKI control-plane path (ESC5)

PRINCIPAL_1a8fce5017e7babdcbd920c3 evidence supports → F01-ESC5 can affect → CertificationAuthoritiesContainer;NTAuthCertificates

Write/control rights over PKI AD objects can let that principal alter certificate trust, publish or modify templates, or change enrollment-service objects. That is a PKI privilege-escalation path if the principal is not an intended PKI administrator.

Requester-supplied identity path (ESC1)

TPL_8a51cba45cc56d7160b059b2 evidence supports → F02-ESC1 can affect → SAN target differs from requester

Requester/SAN identity mismatch on an authentication-capable certificate is the core signal for certificate-based impersonation. Issuance alone does not prove the certificate was used.

Unencrypted RPC enrollment path (ESC11)

CA_2e1fd3acef6dc7f48d1e9451 evidence supports → F03-ESC11 can affect → CA_2e1fd3acef6dc7f48d1e9451

If request traffic is not protected, NTLM relay paths to the CA RPC interface may be possible depending on environment controls.

Enrollment-agent / on-behalf-of path (ESC3)

Enrollment Agent / on-behalf-of issuance evidence supports → F04-ESC3 can affect → Enrollment Agent / on-behalf-of issuance

Enrollment Agent capability can be legitimate, but it can also enable requesting certificates on behalf of other principals if not tightly restricted.

What to do first

  1. Validate F01-ESC5 (ESC5): Confirm whether the principal is an approved PKI/tier-0 administrator and whether each listed ACE is intentional.
  2. Remediate F01-ESC5: Remove GenericAll/GenericWrite/WriteDacl/WriteOwner/WriteProperty from non-PKI-admin principals on the listed PKI objects; retain only explicit, documented PKI admin groups.
  3. Validate F02-ESC1 (ESC1): Correlate the certificate serials/thumbprints or RequestIDs with DC/Kerberos certificate-authentication logs before claiming confirmed misuse.
  4. Remediate F02-ESC1: If unexplained, revoke the certificates and tighten the issuing template's subject/SAN, approval, signature, and enrollment settings.
  5. Validate F03-ESC11 (ESC11): Confirm InterfaceFlags on the CA and whether ICertRequest encryption is enforced.
  6. Remediate F03-ESC11: Enable encrypted ICertRequest enforcement and restart the CA service after validation.
  7. Validate F04-ESC3 (ESC3): Confirm all enrollment agents are authorized and that CA Enrollment Agent restrictions limit which templates and principals they can request for.
  8. Remediate F04-ESC3: Restrict enrollment-agent template enrollment, configure CA Enrollment Agent restrictions, and require authorized signatures on sensitive templates.
  9. Validate F05-ESC4 (ESC4): Confirm whether the principal is an intended template/PKI administrator. Recurring control across many templates may be normal PKI administration, but should be explicitly validated.
  10. Remediate F05-ESC4: Remove Write/Full Control/WriteDacl/WriteOwner from non-PKI-admin principals on certificate templates; use a dedicated PKI admin group.
